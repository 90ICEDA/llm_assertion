## 唯一错误：w5复位释放

实际输入来自已执行的原生开发记录，独立证书保存了来源哈希。

|采样|cycle|rst|mvalid|mready|
|---|---:|---:|---:|---:|
|anchor|2|1|0|0|
|check|3|0|未提供|未提供|

两次模型都返回：

```json
{
  "id": "w5",
  "anchor_cycle": 2,
  "check_cycle": 3,
  "pending": false,
  "reset": true,
  "applicability": "not_required"
}
```

门控要求reset表示check拍是否复位。check拍rst=0，因此应为false。模型的pending=false及not_required标签正确，但reset事件字段错误。第一轮的实际拒绝为：

```json
{"kind":"incorrect_event_reset","id":"w5","expected":false,"actual":true}
```

第二轮请求已包含第一轮真实计划及这一条拒绝诊断，没有发送完整本地期望表。模型仍返回同一个错误。

## 对结论的限制

这个窗口没有待履行的输出保持义务，reset字段错误没有改变其正确的not_required标签。不能把它直接说成新的硬件违例、SVA漏报或全部周期判断错误。本轮封存规则要求事件字段、周期与标签全部正确，因此仍拒绝整体计划；没有事后删除这个检查来追认通过。

其余窗口，包括14→15拍的合法已接受事务变化、22→23拍及另一解除边界的待接受输出义务、持续背压、复位取消等，本批模型的事件与适用性判断通过。这里只证明所给开发窗口上的分项结果。
