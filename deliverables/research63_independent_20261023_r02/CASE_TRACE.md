# 冻结后的原始 decoder 独立轨迹

本批不修改断言、不调用模型。实际模型产生的 research62 接受集合逐字保留，内容哈希为 `1eadd56767c2cc9f1f4e1c8b7ff77f5683b9adf420a1cd9d0cfa4ce61e9f4043`。开发阶段完整151事务已检出420个OP与270个BRANCH点；本次另行测试96个新指令字。

```systemverilog
(instr[6:0] == 7'h63 && (instr[14:12] == 3'b010 || instr[14:12] == 3'b011)) |-> (illegal_insn)
(((instr[6:0] == 51) && (instr[28] == 1))) |-> ((illegal_insn == 1))
```

以下例子直接来自 `case_examples.json` 和原生执行日志，展示新增的 `RV32E=1 / RV32M=0` 配置；`phase=0` 对应 `instr_new=1`，后续保持同一指令字并置 `instr_new=0`。数值为独立编码规则期望和原始RTL的 `illegal_insn_o`，不是测试平台伪造输出。

合法BRANCH例子用于验证OP类别限制：不能把任何指令的bit28=1都判为非法。这里的不触发符合独立义务适用性，不是逃避必要检查。所有必检证据的未触发数均为0。

本批96个词分四类各24个，528个采样×4配置×2原始版本=4224条记录。OP首周期96/96、保持432/432；BRANCH保持432/432。BRANCH首周期两个RTL本来均正确，192条版本/配置记录上均实际触发且不误报，不冒充违例检出。

1936条合法编码记录无误报；全部性质失败均额外接受跨义务归因检查，误报0、unknown0。配置相关的M编码合法性由独立规则判断，不将RV32M=0下正常报告非法当作RTL缺陷。

首批r01保留为曝光规则未满足：我错误地预设BRANCH首周期也应出现该历史缺陷。原始before源码的 `OPCODE_BRANCH` 中，非法编码检查在 `if (instr_new_i)` 内，保持分支漏掉检查；after将检查移到阶段分支外。依据该源码修正规则后，r01全部96个词转为协议开发数据。新批次排除原151词与r01的96词，冻结新规则后才生成新种子及96词；没有重用r01结果作为独立通过证据。

本批结果限于原始decoder模块、两项义务和上述有限配置/样本。不是整核验证、所有编码穷尽或形式化证明；不能据此断言搜索机制有额外收益，或防退化在全局成立。后续若利用本批结果修改候选或规则，整批也须转为开发数据。
