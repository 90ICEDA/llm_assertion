# Manual Golden SVA Table

These golden assertions are human reference assertions chosen for semantic strength and bug-target relevance.
They are not limited to the weaker patterns that happen to be easiest for the current automatic evaluator to score.

| case01_reset_omission | reset omitted | `assert property (@(posedge clk) (!rst_n) |-> (q == 1'b0));` | Whenever reset is sampled low, q must already be 0 in that same sampled cycle. | 0 | `rst_n, q` | overlapping implication (reset-low sampled zero hold) |
| case02_grant_delay | grant delayed by one cycle | `assert property (@(posedge clk) disable iff (!rst_n) (1'b1) |-> (grant == $past(req)));` | After reset is released, each sampled grant must match the previous sampled req with no extra register stage. | 2 | `req, grant` | cycle-by-cycle invariant with history reference (registered req/grant relation) |
